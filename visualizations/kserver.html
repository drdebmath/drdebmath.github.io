The k-Server Problem

k servers sit on a metric space (here, the integer line 0–20). Requests arrive one at a time; each must be served by moving some server onto the requested point. The cost is the total distance moved. An online algorithm sees each request only when it arrives — it is c-competitive if its cost never exceeds c·OPT plus a constant. Compare three strategies on the same request sequence below.

Request sequence — click the line to append a request

Greedy moves the nearest server. It is not competitive: the adversarial sequence keeps poking just past one server while another sits idle, so its cost grows without bound while OPT stays fixed.
Double Coverage moves both neighbours of the request toward it at equal speed (only the nearest one, if all servers are on one side). It is exactly k-competitive on a line — the best possible. The k-server conjecture says a k-competitive algorithm exists in every metric space.
OPT is the offline optimum, computed here by dynamic programming over server configurations. It knows the whole sequence in advance, so its running total is the prefix cost of the final optimal plan — early on it can look worse than an online algorithm.
